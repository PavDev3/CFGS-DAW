# 2.1. Selección de un lenguaje de programación de clientes Web

El lenguaje elegido para la programación en el lado del cliente es **JavaScript**.

## Contexto: por qué JavaScript y no otra cosa

A finales de los 90 y principios de los 2000, los navegadores dependían de plugins externos para crear contenido interactivo (Java Applets, Adobe Flash, VBScript). Con el tiempo, los navegadores modernos se pusieron de acuerdo en un único lenguaje nativo que todos interpretan por igual: **JavaScript**. Hoy en día existen herramientas que mejoran la experiencia de desarrollo (TypeScript, JSX), pero todas ellas acaban traduciéndose a JavaScript puro para que el navegador las entienda.

## Razones técnicas para elegir JavaScript en el front-end

1. **Estandarización e interoperabilidad sin extensiones (zero plugins)**: se ejecuta directamente en cualquier navegador, sin instalar nada adicional ni depender de un plugin propietario.
2. **Reducción de la carga de cálculo y tráfico en el servidor**: al ejecutar la lógica de interfaz en el propio dispositivo del cliente, se evita mandar cada pequeña interacción al servidor.
3. **Modelo asíncrono y no bloqueante, orientado a eventos**: permite reaccionar a clics, teclas o peticiones de red sin paralizar la página mientras se espera una respuesta.
4. **Ecosistema universal (full-stack)**: con Node.js, JavaScript también se usa en el servidor, lo que permite usar un único lenguaje en todo el proyecto.

## JavaScript frente a otras alternativas

| Criterio | JS nativo (Vanilla JS) | TypeScript | JSX |
|---|---|---|---|
| Qué es | Lenguaje estándar interpretado por el navegador | Superconjunto de JS con tipado estático (Microsoft) | Extensión de sintaxis para mezclar HTML con JS (usada por React) |
| Tipado | Débil y dinámico | Fuerte y estático | Hereda el tipado de JS |
| Compilación | Ninguna, se ejecuta tal cual | Obligatoria (se transpila a JS) | Obligatoria (Babel la transforma a JS) |
| Detección de errores | En tiempo de ejecución | En tiempo de desarrollo/compilación | Al compilar los componentes |
| Uso recomendado | Scripts pequeños/medios, manipulación directa del DOM | Aplicaciones grandes (ej. Angular) | Aplicaciones basadas en componentes (React) |

## Conclusión

JavaScript es la opción elegida porque es el único lenguaje soportado de forma nativa y universal por todos los navegadores, sin necesidad de plugins ni pasos de compilación, y porque su modelo asíncrono orientado a eventos encaja con la forma en que el usuario interactúa con una página web. TypeScript o JSX pueden añadirse más adelante como capas sobre JavaScript en proyectos más grandes, pero no lo sustituyen como lenguaje base que entiende el navegador.
